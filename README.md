# OpenRadio

Minecraft 1.21.1 / NeoForge 的**硬核无线电**模组。

不是"加个对讲机"，而是把**传播、设备、功耗、操作手感**当成一个系统来做：
信号会被地形吃掉，换天线能打得更远，没电只能收不能发，频率上挤着别人就会互相盖住。

> 主线是语音。文本、CW、RTTY、SSTV 是同一条无线电链路上的不同呈现，
> 而不是四套互相独立的聊天系统。

---

## 现在能做什么

| 能力 | 状态 |
|---|---|
| 手持电台：调频、开关机、文本收发 | ✅ 可用 |
| 传播模型：距离衰减 + 体素遮挡 + 天气 + 频段差异 | ✅ 可用 |
| 语音：接管 Simple Voice Chat，按信号质量实时劣化 | ✅ 可用 |
| 电池与功耗（NeoForge Energy / FE），低电只能收 | ✅ 可用 |
| 天线（副手，按波段专用）+ 射程增益 | ✅ 可用 |
| 静噪阈值（低于该值当作没有信号） | ✅ 可用 |
| 固定台、CW / RTTY / 加密 / SSTV | 🚧 开发中 |

## 核心设计

**信号质量 Q 是有向且成对的。** `Q(A→B)` 用 A 的功率与天线、A 到 B 的距离和遮挡单独算，
和 `Q(B→A)` 是两次独立计算。同一条消息对不同接收者降级不同 ——
站在旁边的人听得清清楚楚，400 格外的那个只剩一团噪声。

**三种频段互相取舍**，没有"无脑选最远"：

| 频段 | 射程 | 穿透 | 怕天气 |
|---|---|---|---|
| 短波 | 512 | 强 | 低 |
| 中波 | 1024 | 中 | 中 |
| 长波 | 2048 | 弱 | 高 |

**数字模式不伪造物理。** RTTY / CW 走数据协议，音调在客户端本地合成；
SSTV 走真实音频通道，所以接收端是真的在解调一段信号 —— 信号差，图就真的糊。

**服务端权威。** 客户端只上报意图，频率合法性、能否收发、Q 值全部在服务端判定。
设备状态跟着设备自己走（物品数据组件 / 方块实体），不存在会腐坏存档的全局注册表。

## 操作

| 操作 | 说明 |
|---|---|
| 右键电台 | 开关机（需要装着电池） |
| 电台放任意手、另一只手持电池右键 | 装入 / 更换电池 |
| 潜行右键电台 | 拆下电池 |
| `R` | 打开电台面板（调频、报文、静噪） |
| 天线放副手 | 自动生效，装错波段面板里会提示 |

## 依赖

- Minecraft 1.21.1
- NeoForge 21.1+
- **Simple Voice Chat**（语音必需；不装则只剩文本模式）

## 构建

```bash
./gradlew build
```

产物在 `build/libs/`。

开发环境（双客户端联调）：

```bash
./gradlew runClient      # 主客户端
./gradlew runClient2     # 第二个客户端，独立 run2/ 目录
./gradlew runServer      # 专用服务端，独立 run-server/ 目录
```

SVC 本体 jar 需要手动放到 `libs/`（版本见 `gradle.properties`），
它只用于本地运行，不会被打进我们的包里。
