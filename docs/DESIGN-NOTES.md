# Minecraft 硬核无线电通信 Mod 开发文档（草案）

**版本**：v0.1  
**状态**：开发方向定稿，用于后续设计与实现  
**依据**：当前讨论中关于“硬核无线电通信 Mod”的难点拆解、仿真/模拟决策与混合方案

---

## 1. 背景与目标

### 1.1 背景
本项目目标是在 Minecraft 中通过 Mod 实现“硬核无线电通信”，区别于简单 VoIP 或全图聊天。核心体验包括：频率调谐、信号衰减、方块遮挡、天气干扰、人为干扰、中继、设备功耗、加密通信、服务端权威与可配置平衡。

### 1.2 项目目标
- 实现可调频的无线电设备与频道系统。
- 实现简化但可感知的信号传播模拟：距离衰减、方块吸收、天气修正、干扰源。
- 将信号质量映射为语音/文本效果，而非完整 DSP 仿真。
- 支持中继器、固定站、基础加密、电池/功耗。
- 服务端权威计算，客户端只负责表现与输入。
- 保证主线程安全、性能可控、参数可配置。
- 提供渐进式硬核体验：先可用，再硬核。

### 1.3 非目标
- 不做完整电磁场、多径相位、衍射、电离层、多普勒与实时 DSP 仿真。
- 不自研实时 VoIP 音频传输，语音优先复用 Simple Voice Chat。
- 不做全图未加载区块的逐方块实时传播仿真。
- 不映射现实法规频段，使用虚构频段避免法律问题。

## 2. 术语与设计原则

### 2.1 术语
- **仿真实现**：真实计算信号、传播、信噪比、调制解调、误码率等。
- **模拟效果**：用距离阈值、随机数、UI 与音效表现“像无线电”。
- **信号质量 Q**：0.0–1.0 的归一化质量，用于驱动语音/文本效果。
- **中继站**：接收某频率信号后重新发射的固定设备。
- **固定站**：可持久化、可在未加载区块提供有限服务的设备。

### 2.2 设计原则
1. **服务端权威**：频率、位置、信号质量、干扰、功耗由服务端判定。
2. **主线程安全**：异步线程只读快照，不直接访问世界；结果回主线程应用。
3. **简化仿真 + 效果表现**：核心信号层做简化仿真，音频/文本层只模拟效果。
4. **参数可配**：频段、方块吸收、天气修正、干扰器、计算间隔全部可配置。
5. **渐进式硬核**：基础设备易用，高级设备提供加密、定向天线、中继、干扰战。
6. **性能优先**：按需计算、LOD、限频、缓存，避免每 tick 全图射线追踪。

## 3. 总体架构

```
┌──────────────────────────────────────────────┐
│ 客户端层                                      │
│ UI/HUD、调频界面、信号强度、音频效果、输入     │
├──────────────────────────────────────────────┤
│ 网络层                                        │
│ C2S：调频/发射/设备操作请求                    │
│ S2C：信号质量参数、频道状态、设备状态           │
├──────────────────────────────────────────────┤
│ 服务端核心层                                  │
│ 设备注册、频率管理、传播计算调度、中继路由       │
│ 干扰计算、功耗、加密校验、持久化                │
├──────────────────────────────────────────────┤
│ 异步计算层                                    │
│ 主线程快照 → 异步计算 Q → 主线程队列应用        │
├──────────────────────────────────────────────┤
│ 集成层                                        │
│ Simple Voice Chat API、Minecraft 声音、配置、API│
└──────────────────────────────────────────────┘
```

### 3.1 客户端职责
- 渲染调频 UI、频道预设、信号强度、电池、加密状态。
- 发送操作请求，不自行判定通信成功。
- 根据服务端下发的 Q 值播放噪声、低通、断音、音量变化。
- 文本通信根据 Q 值显示错字、乱码、延迟或静音。

### 3.2 服务端职责
- 维护所有无线电设备、频率、中继、干扰器状态。
- 周期性调度传播计算。
- 校验发射权限、电量、加密密钥、频率合法性。
- 将 SignalResult 同步给相关接收端。
- 持久化设备与固定站数据。

### 3.3 异步计算层
- 主线程收集快照：设备位置、维度、天气、方块采样、干扰器、天线方向。
- 异步线程只基于快照计算，不访问 World。
- 计算结果放入主线程队列，由主线程应用到设备与网络同步。
- 禁止在异步线程修改方块、实体、Capability/Attachment。

## 5. 信号计算模型

### 5.1 简化仿真公式
核心信号层采用简化仿真，而不是完整物理仿真：

```text
Q_raw = P + G - L_distance - L_block - L_weather - L_interference + N
Q = clamp(normalize(Q_raw), 0, 1)
```

其中：
- `P`：发射功率等级。
- `G`：天线增益，定向天线按角度判定。
- `L_distance`：距离衰减，建议 `k1 * log10(max(d,1))` 或分段衰减。
- `L_block`：方块吸收，通过 DDA 射线采样累加，设上限。
- `L_weather`：天气修正，如下雨 -4、雷暴 -8。
- `L_interference`：同频干扰、邻频干扰、干扰器。
- `N`：随机噪声，按频段与设备等级配置。

### 5.2 频段参数
每个频段配置：
```text
bandId, 最大距离, 距离衰减系数, 方块穿透系数,
天气敏感度, 邻频抑制, 可用调制模式, 默认噪声
```
建议先做 3–5 个虚构频段，不映射现实法规频段。

### 5.3 Q 值到效果映射
| Q 范围 | 语音表现 | 文本表现 |
|---|---|---|
| 0.8–1.0 | 清晰 | 正常 |
| 0.5–0.8 | 轻微噪声、音量略降 | 偶发错字 |
| 0.2–0.5 | 明显噪声、低通、断音 | 高频错字、乱码片段 |
| 0.0–0.2 | 静音或强噪声 | 乱码/不可读 |

### 5.4 计算调度
- 默认每 N tick 计算一次，N 可配置。
- 活跃设备优先；远距离或低功耗设备降低更新频率。
- 射线采样设最大步数，避免长距离高成本。
- 反射、多径、衍射只做“效果级”表现，不做完整递归物理。

## 6. 语音与文本通信

### 6.1 语音
- 不自研 VoIP。
- 优先集成 Simple Voice Chat API。
- 服务端计算并同步接收端的 Q 值。
- 客户端根据 Q 值添加噪声、低通、断音、音量衰减。
- 语音隐私与录音策略沿用 Simple Voice Chat 或服务器配置。

### 6.2 文本/数据
- 支持文本消息、预设短消息、数字模式。
- 根据 Q 值进行错字、乱码、延迟、丢失。
- 加密模块：无密钥听到噪声或乱码；有密钥恢复正常。
- 加密只做游戏内虚构实现，避免现实强加密出口限制讨论。

---

## 7. 线程安全与网络同步

### 7.1 线程安全规则
1. 异步线程不得访问 World、Level、Entity、BlockEntity。
2. 主线程负责生成只读快照。
3. 异步线程计算纯数据。
4. 结果通过线程安全队列回主线程。
5. 所有世界修改、网络包发送、设备状态变更在主线程执行。
6. 提供调试开关记录异步任务耗时与队列积压。

### 7.2 网络同步
- C2S：调频、开关机、发射请求、加密操作、预设管理。
- S2C：Q 值、频道占用、干扰状态、电池、设备状态、UI 提示。
- 语音流走 Simple Voice Chat，Mod 只同步质量参数。
- 限频同步，避免大量玩家与设备造成带宽压力。
- 服务端权威，客户端不可伪造位置、频率、Q 值。

## 8. 区块加载与中继策略

### 8.1 已加载区块
正常参与传播计算、射线采样、设备更新。

### 8.2 未加载区块
- 玩家手持/移动设备在未加载区块不工作。
- 只支持持久化固定中继站/固定信标。
- 固定站按拓扑与预设范围计算，不做逐方块射线。
- 中继器可链式转发，但限制最大跳数与最大数量。
- 未加载区域的中继服务为“简化服务”，不保证完整物理仿真。

## 9. 设备与玩法模块

### 9.1 设备类型
- 手持电台：基础调频、短距离、电池。
- 固定电台：高功率、外接天线、可持久化。
- 中继站：接收并重发，支持固定频率。
- 干扰器：范围内增加干扰，影响 Q 值。
- 加密模块：频道密钥，无密钥乱码/噪声。
- 天线：全向/定向，高度与方向提供增益。

### 9.2 UI
- 调频、扫描、频道预设、静噪码。
- 信号强度、电池、加密状态、干扰提示。
- 简单频谱/信号条，不做完整实时频谱图。
- 教程与游戏内手册，渐进解锁高级设备。

## 10. 配置与平衡

建议提供配置文件：
```text
频段表、方块吸收表、天气修正表
干扰器强度与范围
最大设备数、最大中继跳数
传播计算间隔 tick
射线最大步数
Q 值效果阈值
电池容量与发射功耗
加密开关与密钥规则
调试日志与性能统计
```

平衡目标：
- 基础设备可用但不全图。
- 中继与高功率设备提供扩展范围。
- 干扰与加密形成对抗玩法。
- 参数可调，方便服务器管理员平衡。

## 11. 兼容性与技术选型

- 先支持一个加载器与一个 Minecraft 版本，建议 Fabric 或 NeoForge 二选一。
- Simple Voice Chat 作为可选/推荐依赖。
- 提供频道事件 API，便于其他模组接入。
- 避免与地图、聊天、语音模组硬冲突。
- 不映射现实频段，使用虚构频段与设备名。

## 13. 测试计划

- **单元测试**：距离衰减、方块吸收、天气修正、Q 值映射。
- **集成测试**：多玩家、多设备、同频干扰、中继链。
- **性能测试**：大量设备、长距离射线、异步队列积压。
- **线程安全测试**：异步计算与主线程快照一致性。
- **反作弊测试**：客户端伪造频率/位置/Q 值。
- **兼容测试**：Simple Voice Chat、常见聊天与地图模组。
- **平衡测试**：不同频段、功率、天线、干扰器组合。

## 14. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| 异步访问世界导致崩档 | 严格快照机制，异步只算纯数据 |
| 射线追踪性能爆炸 | 限步数、限频、LOD、缓存 |
| 语音集成复杂 | 复用 Simple Voice Chat，只同步 Q 值 |
| 未加载区块仿真成本高 | 只支持固定中继，拓扑简化 |
| 太硬核劝退休闲玩家 | 渐进解锁、教程、可配置 |
| 平衡困难 | 全部参数化，提供服务器配置 |
| 法律与频段问题 | 使用虚构频段，不映射现实法规 |

**文档结论**：本项目采用“核心信号层简化仿真 + 音频/文本层效果模拟 + 服务端权威 + 异步安全计算 + 固定中继有限持久化”的混合路线。该路线能在可控开发成本内实现硬核无线电体验，同时避免完整电磁仿真、实时 DSP 与全图未加载区块计算带来的高风险。
